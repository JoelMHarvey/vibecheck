What it checks

Leaked keys & secrets

Anthropic, OpenAI, Stripe (live vs test), AWS, Google, GitHub, Slack, Telegram, private keys, database URLs with passwords. Secrets in browser code are escalated — every visitor has them.

Supabase-aware

Hardcoded JWTs are decoded: a service_role key (bypasses all Row Level Security) is critical; an anon key becomes a reminder to verify RLS.

Vibe-coding mistakes

dangerouslyAllowBrowser, LLM APIs called from the frontend, secrets in VITE_/NEXT_PUBLIC_ variables, .env not gitignored.

Classic vulnerabilities

SQL built by string interpolation, shell injection, XSS via innerHTML, eval, CORS open to every origin, debug mode left on.

Your deployed site

Publicly readable .env or .git, published source maps that rebuild your source, missing security headers, plain HTTP, and robots.txt that signposts your admin pages.

Prefer the command line?

The same scanner, fully offline, zero dependencies (Python 3.9+). Drop it into CI — it exits 1 on high/critical findings.

python3 -m vibecheck /path/to/your/app --markdown report.md
python3 -m vibecheck --url https://myapp.com
python3 -m vibecheck --visibility https://myapp.com

Two rules of thumb: browser code cannot keep a secret, and deleting a leaked key does not un-leak it — rotate it.
